# Slither Arena

[Играть онлайн](https://gkdfkgdfg.github.io/slither-arena-optimized/) · [Репозиторий](https://github.com/gkdfkgdfg/slither-arena-optimized)

Браузерная игра со змейками, оптимизированным Canvas-рендером и сервером на Node.js без внешних зависимостей. Это одиночная игра с ботами и виртуальным балансом.

## Запуск

Нужен Node.js 20 или новее. Установка npm-пакетов и сборка не требуются:

```sh
node server.js
```

Открыть http://127.0.0.1:3000/. В Windows также можно запустить `START_GAME.bat`. Для остановки — Ctrl+C.

Настройки сервера: переменные окружения `PORT` (по умолчанию 3000) и `HOST` (по умолчанию 127.0.0.1). На хостинге Node.js обычно требуется `HOST=0.0.0.0`. Сервер поддерживает Brotli/Gzip, ETag, HEAD, кэширование ресурсов и ограниченный кэш в памяти. Исходник сервера, тесты, `.git` и конфигурация через него не публикуются. Проверка работоспособности — `/api/health`.

## Управление

- Мышь / палец — направление движения.
- Space, кнопка BOOST, зажатая кнопка мыши или второй палец — ускорение с расходом добычи.
- Esc / кнопка паузы — пауза.
- После достижения ×37,5: Q, кнопка «ЗАБРАТЬ», нажатие на сумму или зелёная граница — выход с добычей.
- Красная граница смертельна. Свой хвост безопасен. При встречном столкновении голов погибают обе змеи.

В меню доступно качество «Авто / Высокое / Среднее / Низкое». Автоматический режим снижает разрешение при устойчивых медленных кадрах. Настройки и виртуальный баланс хранятся в браузере, на конкретном устройстве.

## Что исправлено

- Отрисовка текстур полосами и кэшированными круглыми стыками вместо тысяч треугольных Canvas-клипов за кадр.
- Пространственная сетка для монет, удаление за O(1), ограничение количества монет и очистка старой добычи.
- Физика 60 Гц с интерполяцией тела и камеры, ограничением догоняющих шагов и остановкой скрытой вкладки.
- Ограничение числа пикселей Canvas, выбор качества, более быстрая реакция на медленные кадры.
- Подписи сумм обновляются максимум 10 раз в секунду и используют существующий Canvas.
- Убраны запланированные самоубийства ботов. Боты собирают еду и избегают тел.
- Столкновения ботов с телами теперь смертельны, как у игрока. Добавлены столкновения голов; расширен радиус поиска для толстых змей.
- Работают Q и Cash Out; состояния границы различаются цветом. Пауза, звук и ускорение доступны на мобильном экране.
- Ускорение заметно расходует добычу, сохраняет положительный минимум; выпавшая добыча сохраняет стоимость погибшей змеи при меньшем числе шариков.
- Новые соперники выбирают стоимость из диапазонов размера, без подгонки награды под требуемую кривую выигрыша игрока.

## Проверка

```sh
node --test
```

Автоматические проверки: пространственные запросы после перемещений и удаления, целостность индексов, расход ускорения, отсутствие потери стоимости, HTTP-ресурсы, сжатие, ETag, HEAD и защита приватных путей.

В браузере дополнительно проверены 13 сценариев: блокировка раннего выхода, пауза, ускорение, конечные координаты тела, целостность сетки, число и стоимость выпавших шариков, красная/зелёная границы, встречное столкновение ботов, отсутствие самоубийств по таймеру, предел монет и их индексы. Клавиша Q проверена через интерфейс. Вёрстка проверена при размерах 1280×720 и 390×844. Физический телефон в этой проверке не использовался.

### Контрольная сцена рендера

Один и тот же браузер, окно 1280×720, DPR 1,5: 10 змей по 700 точек с фиксированными координатами, 2600 монет, 3 прогрева и 40 вызовов `render()`.

| Показатель | Исходная версия | Эта версия |
| --- | ---: | ---: |
| Медиана выполнения JS в `render()` | 7,1 мс | 2,0 мс |
| 95-й перцентиль | 186,6 мс | 6,0 мс |
| Canvas `clip()` на кадр | 2187 | 0 |
| `drawImage()` на кадр | 3386 | 1737 |

Измерены расходы на выполнение кода и отправку Canvas-команд; это не полное время работы GPU и не обещание конкретного FPS на любом телефоне. Перцентиль особенно чувствителен к окружению и короткой выборке. Для монет в той же сцене после одной смерти: 462 кандидата в соседних ячейках против 27 280 проверок при полном обходе. Результаты находятся в `PERFORMANCE.json`.

Диагностика в консоли браузера: `gameDiagnostics()` — частота кадров, время update/render, DPR, количество монет и проверок. Поведение в обычном раунде зависит от устройства, карты, масштаба и количества видимых змей.

## Публикация

Клиент не использует API игры и может запускаться на GitHub Pages. GitHub Pages раздаёт статические файлы и не запускает `server.js`; тот нужен для локального запуска или отдельного Node.js-хостинга. Публичная ссылка позволяет другим людям играть в собственные раунды с ботами. Общая мультиплеерная арена и серверная синхронизация игроков в этой версии отсутствуют.

## Файлы

`mystake.js` — игровой цикл и интерфейс; `game-core.js` — сетка монет и базовые операции; `mystake-art.js` — отрисовка; `mystake-physics.js` — движение тела; `mystake-bots.js` — ИИ; `mystake-maps.js` — карты. Текстуры находятся в `skins/`, `flags/`, `maps/`, шрифты — в `fonts/`.

Основа — публичный клиент https://fgfsdgfgsdasgrf4.vercel.app/, скачанный 11 ноября 2026 года. Исходный архив сохранён отдельно в рабочей папке. В этот репозиторий не входят приватный исходный репозиторий, видео и генераторы ресурсов исходного проекта.
